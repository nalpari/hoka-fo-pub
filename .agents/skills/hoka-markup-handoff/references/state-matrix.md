# 상태 선정과 분리 기준

서비스·시연 흐름 제거와 고정 상태 인계의 [적용 원칙](../SKILL.md#적용-원칙)을 따른다. 구조·스타일 정리만으로 모든 상태 URL을 추가하지 않는다.

모든 행을 조사 기준으로 사용하되 모든 화면에 모든 상태를 만들지 않는다. 기존 디자인·소스·story·명시적 요구가 있고 독립적으로 확인할 의미가 있는 상태를 선택한다.

| 분류 | 구별할 상태 | 별도 확인 기준과 예시 |
| --- | --- | --- |
| 기본/초기 | 정상 데이터, 입력 전 안내, 아직 조회하지 않음 | 기본 URL이 맡는다. 조회 전 안내는 조회 완료 후 Empty와 다르다. 필요하면 `preview-initial`로 구분한다. |
| Empty | 장바구니·주문·주소·쿠폰·리뷰 등의 보유 데이터 없음 | 주요 콘텐츠가 안내/CTA로 대체되면 `preview-empty`. 헤더 건수·합계·버튼 노출도 상태와 일치시킨다. |
| No results | 검색·필터·기간 조건에 맞는 결과 없음 | 보유 데이터 없음과 안내·조건 초기화 UI가 다르면 `preview-no-results`. 조건 영역은 유지한다. |
| 필드 오류 | 필수값 누락, 형식 오류, 불일치, 중복, 약관 미동의, 첨부 오류 | 서로 다른 마크업·배치·문구가 있으면 대표별 직접 URL. 같은 표현의 문구 차이는 fixture/story로 충분한지 판단한다. 모든 오류 동시 표시가 불가능한 제품이면 그런 조합을 만들지 않는다. |
| 요청/페이지 오류 | 조회 실패, 제출 실패, 인증 실패, 네트워크 안내 | 필드 오류와 구분한다. `preview-load-error`, `preview-submit-error` 등. 제출 실패는 입력값 유지 형태, 조회 실패는 Empty로 위장하지 않는 형태를 확인한다. 실제 요청은 실행하지 않는다. |
| Loading | 첫 조회 skeleton/spinner, 재조회 중, 더보기 로딩 | 디자인이 있으면 `preview-loading`. 첫 화면과 기존 데이터 유지 로딩은 구조가 다르면 분리한다. 영구 대기 fixture여도 실제 요청은 없다. |
| Pending | 제출/업로드/인증 처리 중, 버튼 spinner·disabled | `preview-pending`에서 상태를 고정한다. Empty나 일반 disabled와 구분한다. 타이머·네트워크로 상태를 연출하지 않는다. |
| Success/Complete | 가입·주문·신청·반품·등록 완료, 복구 결과, 인라인 성공 안내 | 기존 완료 URL을 우선 재사용한다. 업무 성공을 실제로 수행하지 않는다. 전체 결과 화면과 짧은 toast는 분리 필요성이 다르다. |
| 접근/계정 제한 | 비로그인, 권한 없음, 계정 잠김·휴면·탈퇴, 재인증 필요 | 실제 디자인 근거가 있는 경우만 직접 URL. 실제 계정/세션을 바꾸거나 middleware의 보안을 완화하지 않는다. |
| 리소스 없음 | 삭제·미존재 상품/게시글, 잘못된 링크, 404 | Empty 목록과 다르다. 기존 not-found 표현을 재사용할 수 있으나 framework 동작은 보존한다. |
| 기간/이용 제한 | 인증 만료·시간 초과, 쿠폰 만료, 신청 종료·정원 마감·오픈 예정 | 업무 용어와 버튼/안내 차이를 기준으로 선택한다. 날짜 계산·카운트다운 대신 고정 표시를 사용한다. |
| 상품/행 상태 | 품절·판매중지·선택 불가, 배송 제한, 사용 완료 | 대표 행 하나로 기본 화면에서 확인 가능한지 먼저 본다. 전체 페이지 안내/액션이 달라지면 `preview-sold-out` 등으로 분리한다. |
| 부분 상태 | 일부 행 실패·일부 품절, 영역별 오류, 더보기 실패, 이미지 대체 | 전체 실패/Empty와 구분한다. 정상 콘텐츠가 함께 남는 의미 있는 대표 조합만 선택한다. |
| 선택/조건 상태 | 전체·일부 선택, 옵션 미선택, 배송지 없음, 첨부 있음, 최대 입력 | 작은 선택 스타일은 UI 조작/story로 확인한다. 주요 영역이나 CTA 구조가 달라지고 직접 인계가 필요하면 preview로 제공한다. |
| Overlay/알림 | 확인·경고·완료 modal, drawer, toast | 단순 열기/닫기는 기본 UI 유지. 오류/빈 목록이 modal 내부에만 있거나 전용 검수가 필요하면 열린 상태 preview. focus trap·Escape·닫기 복원을 보존하고 일반 콘텐츠로 펼쳐 대체하지 않는다. |
| 콘텐츠 경계 | 한 건·다수·긴 제목·긴 오류·이미지 없음·마지막 페이지 | 보통 fixture/story로 커버한다. 별도 레이아웃이나 명시적 인계 요구가 있을 때만 URL을 추가한다. 반응형과 조합 폭증을 피한다. |

## 판단 순서

1. 기존 전용 URL로 직접 확인되면 재사용하고 screen-index에 연결한다.
2. 주요 콘텐츠가 바뀌거나 시각 검수를 위해 복잡한 선행 조작이 필요하면 직접 preview URL로 분리한다.
3. 작은 상태 차이이고 기본 화면에서 즉시 조작 가능하면 기본 UI와 story를 유지한다. 사용자가 별도 URL을 요구한 상태는 직접 URL로 제공한다.
4. 같은 UI/의미의 중복 사례는 합친다. 같은 이름이라도 Empty와 No results, 필드 오류와 페이지 실패처럼 의미와 구조가 다르면 나눈다.
5. 기존 근거가 없으면 `디자인/요건 미확정`으로 기록한다. 임의 화면을 채워 넣지 않는다.

| 폼/해당 IA | 요청 처리 중 | 제공된 디자인 없음 | 요건 미확정, 생성 보류 | 미등록 | 해당 없음 |
