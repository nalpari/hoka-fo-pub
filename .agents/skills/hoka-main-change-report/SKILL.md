# HOKA main 변경 보고

수동 실행 시 최신 `origin/main`을 확인하고, 개발자가 어디를 수정·확인해야 하는지 IA와 소스 근거로 정리한다. 예약이나 17시 마감 기준은 사용하지 않는다. 스킬 생성·검토 요청이면 스킬만 다루고 실제 보고는 실행하지 않는다.

## 호출과 비교 범위

```text
$hoka-main-change-report 72ae26eb09661ccc346556b3ad0ef36417e53010
$hoka-main-change-report
```

- 해시를 지정하면 **그 커밋의 변경을 포함**한다. 저장된 기준보다 명시한 해시를 우선한다. 예시 해시의 제목도 실제 Git에서 읽으며 예시 문구를 고정 출력하지 않는다.
- 해시 없이 호출하면 마지막 성공 보고 SHA **이후**부터 비교한다. 처음 실행하거나 상태가 없으면 시작 SHA 또는 날짜를 사용자에게 확인한다. 날짜를 받으면 한국 시간 범위와 실제 시작 커밋을 보여 주고 확정한 뒤 진행한다. 임의로 당일이나 전체 이력을 선택하지 않는다.
- 먼저 저장소 `AGENTS.md`, `okf/index.md`와 IA 관련 개념을 읽는다. `git fetch origin` 성공 직후 `origin/main`의 전체 SHA를 종료점으로 고정하고 Asia/Seoul 수집 시각을 기록한다. 이후 원격이 움직여도 이번 보고의 종료점은 바꾸지 않는다.
- 입력은 SHA로 검증하고 `git rev-parse --verify --end-of-options <hash>^{commit}` 등으로 전체 SHA를 얻는다. 입력을 셸 명령 문자열에 결합하지 않는다. 짧은 해시가 모호하거나 커밋이 없으면 알린다.
- 시작 커밋과 저장된 기준이 종료점의 조상인지 확인한다. fetch 실패, 기준 소실·이력 재작성·다른 브랜치 커밋이면 원인을 알리고 멈춘다. 로컬 main이나 현재 브랜치로 조용히 대체하지 않는다.
- checkout/reset/pull/stash/rebase는 수행하지 않는다. 인덱스와 관련 working-tree diff·미추적 파일 내용을 저장소 밖에 기록하고 다른 작업을 보존한다.

## 최종 유효 변경 분석

- 명시한 시작 커밋을 S, 고정한 종료점을 T라 하면 비교 기준 B는 S의 첫 번째 부모다. 병합 커밋도 첫 부모 대비 변경을 포함한다. S가 루트 커밋이면 해당 저장소 형식의 빈 tree를 B로 쓴다. 저장된 성공 SHA로 이어갈 때는 그 SHA 자체가 B다.
- `git diff --find-renames B T`를 최종 변경의 기준으로 삼고 name-status와 실제 patch를 모두 읽는다. `B..T`의 커밋 목록은 근거 추적용이지 변경 항목 목록이 아니다. 두 점 대신 세 점 diff로 범위를 바꾸지 않는다.
- `.md` 파일 변경은 IA 이력과 공유 보고서에서 제외한다. 이름변경의 이전/이후 경로 중 하나라도 `.md`이면 제외한다. 원본 diff 수와 Markdown 제외 후 보고 파일 수를 구분한다.
- 퍼블리싱 가이드 전용 파일(`src/app/publishing-guide/`)과 IA 구조도 자체(`src/app/screen-index/`, `src/data/screenRegistry.ts`, IA 전용 테스트)의 변경도 보고 목록에서 제외한다. IA 담당자·소스 연결은 매핑 근거로만 읽는다. 제품에서 사용하는 공용 UI·SVG는 가이드에도 쓰인다는 이유로 제외하지 않는다.
- Git author 이름이 `nalpari`인 커밋의 기여를 제외한다(대소문자 무시). 최종 diff와 blame·커밋별 patch를 대조한다. 전체가 해당 작성자의 변경이면 파일을 제외하고, 같은 파일에 다른 작성자의 유효 변경이 남으면 그 영역은 유지한다. 새 파일의 후속 수정도 최초 기능 전체 대신 남은 영역만 설명한다. 작성자와 제외 판단 근거는 내부 분석용으로만 보관한다.
- 범위 안에서 적용 후 완전히 원복되어 B와 T가 같은 내용은 보고와 IA 추가 항목에서 제외한다. 부분 원복은 남은 hunk만 보고한다. `revert` 제목이나 파일명 겹침으로 커밋 전체를 제외하지 않는다. 하나의 커밋에 남은 변경과 원복된 변경이 함께 있을 수 있다.
- 이전 보고 시점에 존재했던 기능이 이번 범위에서 원복되었다면 유효한 삭제·복구 변경으로 보고한다. 최종 diff가 비었으면 `최종 유효 변경 없음`으로 기록한다.
- 남은 hunk의 함수/컴포넌트, B 기준 이전 줄 범위와 T 기준 이후 줄 범위, 사용자에게 보이는 동작 또는 인계 계약 변화를 확인한다. 추가·삭제·이름변경·바이너리를 구분하고 없는 줄 범위나 바이너리 내부 변경을 발명하지 않는다. 줄 번호 링크는 해당 SHA의 파일로 연결한다.
- 병합 및 squash에서는 first-parent diff, 필요 시 부모별 diff·blame·파일 log로 최종 유효 변경을 교차 확인한다. 분석용 커밋 근거는 내부 데이터로만 유지한다. IA와 공유 보고서에는 커밋 작성자·기여 커밋 목록·파일별 관련 SHA를 표시하지 않는다. 비교 범위를 나타내는 시작/종료 SHA와 시작 커밋 제목은 유지한다.

## IA 연결과 담당자

- 현재 IA 구조도의 `src/data/screenRegistry.ts`, `src/app/screen-index/screenConnections.ts`, `screenDevelopers.ts`와 렌더러를 읽는다. **개발담당자는 IA에 등록된 값을 그대로 사용**한다. Google Drive·Sheets·WBS는 조회하지 않고 매핑을 변경하지 않는다. 공란은 `미지정`으로 표시하며 과거 담당자를 추정하지 않는다.
- 제품 변경 분석은 B/T 소스에서 수행하고 IA/담당자 매핑을 읽은 리비전과 작업 트리 사용 여부를 별도 기록한다. 로컬 미커밋 제품 변경을 main의 변경으로 섞지 않는다.
- `getRouteSourceFiles`는 인계용 목록이므로 전체 영향 탐색의 유일한 기준으로 사용하지 않는다. 비교 전후 전체 import 관계를 역추적해 page·layout과 연결된 IA를 찾는다. `scripts/screen-files.mjs`의 `buildSourceGraph` 등 기존 분석기를 참고하되 B/T를 저장소 밖 임시 스냅샷에서 분석하고 공유 생성 파일을 덮어쓰지 않는다. 현재 그래프를 과거 리비전의 그래프로 간주하지 않는다.
- 공통 UI·삭제/이름변경 파일·layout·전역 스타일·public 에셋·설정·문자열/동적 참조도 확인한다. 정적 import 그래프로 증명되지 않는 영향은 `영향 가능` 또는 `연결 확인 필요`로 구분한다. 직접 수정 파일과 영향 화면을 분리하고 IA에 연결되지 않는 파일도 보고서에서 누락하지 않는다.
- 공통 변경은 실제 소유자 기준으로 한 번 분류한다. STATE 공통은 상위 화면, D4 목록/상세의 공통은 실제 D3 분류 등 기존 소유권을 매핑 근거로 사용한다. 이 분류는 보고 데이터의 담당자·변경사항에 사용하며 각 IA 행에 새 비고나 보고서 버튼을 추가하지 않는다. 기존 상품 공통 수동 비고는 그대로 보존한다.
- 상태 URL의 query/hash를 보존하고 같은 pathname의 다른 상태를 합치지 않는다. 소유자가 여러 영역에 걸치면 대표 화면을 발명하지 말고 공통 변경으로 구분한다. 전역 레이아웃의 간접 의존만으로 특정 화면이 직접 수정된 것처럼 표시하지 않는다.

## 보고서·IA·실행 상태 저장

이 단계 전에 [출력과 재실행 규칙](references/output-and-state.md)을 읽는다.

- 결과는 한국어 Markdown 공유 보고서와 IA 구조도의 보고서 모달이다. IA의 기존 비고·담당자·작업 파일·상태 링크는 보존하고 각 화면에 보고서 버튼을 추가하지 않는다. 상단 `날짜 Select → 보고서 개발담당자 Select → 퍼블 변경사항 보고서`에서 선택한 조건으로 모달을 연다. 보고서 담당자 선택은 IA 목록 담당자 필터와 독립적이며 공동 담당은 개별 이름으로 매칭한다. 공통 변경도 해당 담당자와 관련된 항목만 포함하고 미지정은 별도로 선택한다. 표는 `개발담당자 | 메뉴 / 화면 | 변경사항 | 변경 파일 * Before | 변경라인 * After`이며 담당자/같은 설명을 rowspan으로 묶는다. SVG 등 이름변경은 Before 열에 B의 이전 경로, After 열에 T의 이후 경로를 나눠 표시하고 일반 수정은 파일과 B/T 줄을 표시한다. collapse 목록·작성자·기여 목록은 출력하지 않는다.
- IA 이력 데이터/표시 기능이 없으면 실행 범위에 필요한 최소 연결만 구현한다. Next.js 관련 코드를 작성하기 전 설치된 가이드와 저장소 규칙을 읽고 관련 OKF를 갱신한다. 화면 재설계나 상태 엔진을 만들지 않는다. 혼합 파일을 안전하게 수정할 수 없으면 보고서를 초안으로 남기고 충돌을 알리며 성공 기준을 갱신하지 않는다.
- 날짜 Select에는 저장된 보고서 날짜만 최신순으로 제공하고 기본값은 최신 날짜다. 보고서 개발담당자는 전체/기존 IA 담당자/미지정을 제공한다. 버튼 클릭 시 선택 날짜·담당자에 맞는 파일 수와 rowspan을 다시 계산한다. 전역 레이아웃 간접 의존성만으로 각 화면 비고에 별도 보고서 연결을 만들지 않는다.
- 모달 제목은 선택 날짜의 `26-11-04 퍼블 변경사항 보고서` 형식이다. `/screen-index?report=2026-11-04`로 직접 접속하면 해당 날짜의 **전체 개발자** 보고서를 자동으로 연다. 특정 담당자는 `&developer=김진영` 또는 `&developer=unassigned`로 지정한다. 담당자 파라미터 생략/빈 값은 항상 전체다. 버튼으로 열 때도 이 URL을 반영하며 새로고침·뒤로/앞으로 이동에 날짜·담당자·열림이 반응해야 한다. 닫기는 보고서 관련 파라미터만 지우고 다른 query/hash를 보존한다. `next/navigation`과 필요한 Suspense 경계를 사용한다.
- 실제 보고서와 IA 결과를 검증한 뒤에만 성공 SHA를 저장한다. 최종 응답에 보고서 링크·비교 SHA·수집 시각·주요 수정·검증과 미확정 사항을 제시한다. 실제 발송·배포와 로컬 파일 생성을 구분한다.
- 자동화 생성·예약, 커밋·푸시·배포·WBS 수정·메일/메신저 발송은 하지 않는다. 보고 자료 생성 자체를 제품 변경으로 오인하지 않는다. 사용자에게 자료 초안만 요청받은 경우 IA 수정과 성공 기준 갱신은 생략하고 초안임을 표시한다.

메뉴 / 화면 열은 파일별로 IA의 전체 메뉴 경로와 화면명을 표시한다(예: 마이페이지 > 구매내역 > 주문배송 조회). 상품 공통 별칭은 상품 목록/상품 상세로 풀어 쓰고, STATE 전용 변경은 query/hash를 포함한 상태 URL도 표시한다. 여러 소유 화면은 모두 유지하며 같은 설명으로 묶여도 파일별 메뉴 정보를 생략하지 않는다. 직접 소유 화면이 없는 공용 UI는 공통 UI·영향 가능 화면으로, 화면에 연결되지 않는 설정/에셋은 화면 외 공통으로 구분한다. 간접 영향 화면을 직접 수정 화면으로 단정하지 않는다. 기존 저장 보고서와 공유 Markdown에도 같은 열을 제공하고, 담당자 필터 후 메뉴 정보·파일 수·rowspan이 유지되는지 검증한다.

URL의 예약 담당자 값 all/unassigned는 대소문자를 구분하지 않고 앞뒤 공백을 제거해 처리한다. 따라서 developer=ALL도 전체 담당자 보고서를 연다. 실제 담당자 이름은 원래 표기를 유지한다.
