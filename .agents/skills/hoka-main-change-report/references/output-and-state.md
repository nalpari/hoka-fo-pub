# 출력과 재실행 규칙

## 공유 보고서

저장소 루트의 `reports/main-changes/<reportId>.md`에 UTF-8로 저장한다. 기존 사람이 작성한 파일은 덮어쓰지 않는다. `reportId`는 전체 B/T와 비교 방식(`inclusive` 또는 `resume`)으로부터 결정되는 안정적인 식별자다. 예: `inclusive-<B 전체 SHA>-<T 전체 SHA>`. 재실행은 같은 생성 보고서와 이력 항목을 갱신하며 다른 비교 범위는 별도 보고서로 보존한다.

보고서에는 다음 내용을 담는다. 내용 없는 형식적 항목은 생략할 수 있지만 미매핑 파일과 검증 한계는 숨기지 않는다.

1. **비교 근거**: 저장소/원격, 요청 시작 SHA·제목과 포함 여부, 실제 B/T 전체 SHA, 수집 시각(Asia/Seoul), IA·담당자 매핑 리비전/작업 트리 출처, 성공/초안 상태.
2. **개발자별 전달 사항**: IA의 개발담당자별로 해야 할 확인을 요약한다. 공동 담당은 현재 표기를 보존하고 미지정을 따로 표시한다.
3. **유효 변경 표**: `개발담당자 | 변경사항 | 변경 파일 * Before | 변경라인 * After`. 같은 담당자와 설명은 rowspan으로 묶고 collapse 목록은 사용하지 않는다. 이름변경은 Before/After 경로를 분리하며 일반 수정은 파일·B/T 줄 범위를 표시한다. Markdown·가이드·IA 자체 변경과 nalpari 작성자의 기여를 제외하고 커밋 작성자·기여 목록·파일별 관련 SHA도 출력하지 않는다.
4. **공통 영향과 미매핑**: 직접 수정과 정적 의존에 따른 영향 가능 화면을 구분하고 설정·문서·에셋 등 IA 밖의 변경도 요약한다. 제품 구현 이외 변경은 구분해 표시한다.
5. **검증**: 실제 수행한 검사, 아직 수행하지 않은 시각/서비스 검증과 확인 필요 사항.

비교/파일 링크는 확인한 원격 URL에서 만든다. 불명확하면 비교 SHA와 경로만 표시한다. 표의 줄 범위는 B/T 기준임을 표시한다. 제외 파일은 보고 건수에서도 제외하고 이유별 제외 수와 혼합 파일에서 빠진 영역 수를 내부 데이터에 보존한다. 분석용 커밋 근거를 보관하더라도 표시 자료에서는 작성자와 기여 목록을 제거한다. 원복된 중간 시행착오를 공유 본문에 나열하지 않는다. 모든 변경이 상쇄되었거나 제외 파일만 남으면 비교 근거와 `보고 대상 유효 변경 없음`을 제공한다.

## IA 보고 데이터와 모달

기존 구조화 보고 데이터를 재사용한다. 없으면 `src/app/screen-index/` 아래 최소 데이터와 모달 연결만 추가한다. 기존 IA 수동 비고와 담당자·상태 링크를 보존하며 화면별 보고 버튼과 collapse 목록은 만들지 않는다.

- reportId·B/T·수집 시각·파일별 정확한 영역·내부 분석 근거·소유자/관련 IA와 제외 집계를 보존한다. 동일 범위 재실행은 해당 reportId 데이터만 갱신하고 다른 날짜의 보고서와 수동 비고를 보존한다.
- IA 소유권은 담당자와 소스 연결을 판단하는 근거이며 광역 공통 import를 화면의 실제 수정으로 간주하지 않는다. 제품 분석은 B/T 스냅샷을 사용하고 현지 작업 트리 변경은 섞지 않는다.
- 상단 날짜 Select는 저장된 날짜만 최신순으로 제공한다. 그 옆 보고서 개발담당자 Select는 IA 목록 필터와 독립적으로 전체/개별 담당자/미지정을 선택한다. 공동 담당도 개별 이름으로 매칭하고 같은 파일은 한 번만 표시한다.
- 선택한 날짜와 담당자로 보고서를 연다. 표의 파일 수와 담당자/설명 rowspan은 필터 결과로 다시 계산한다. 이름변경은 Before/After 경로를 분리하고 일반 수정은 파일과 줄 범위를 표시한다. 결과가 없으면 선택 조건에 해당하는 변경이 없다고 표시한다.
- 닫기/Escape는 실제 보고서 버튼으로 포커스를 복원하고 IA 검색·목록 담당자와 보고서 날짜·담당자 선택을 보존한다. 모바일은 fullscreen과 표 내부 스크롤을 사용한다.
- 제목은 `26-11-04 퍼블 변경사항 보고서` 형식이다. `/screen-index?report=2026-11-04`는 전체 개발자, `&developer=김진영`은 해당 담당자, `&developer=unassigned`는 미지정이다. 담당자 생략/빈 값은 전체다. URL 직접 진입·새로고침·브라우저 뒤로/앞으로 이동을 지원하고 버튼으로 열 때도 URL을 갱신한다. 닫기는 report/developer만 제거하며 다른 query/hash와 IA 상태를 보존한다. 존재하지 않는 날짜는 다른 날짜로 대체하지 않고 보고서 없음으로 표시한다.

## 실행 상태와 실패

`git rev-parse --path-format=absolute --git-common-dir`로 얻은 디렉터리 아래 `codex/main-change-report/state.json`을 사용한다. 특정 컴퓨터의 `.git` 절대 경로를 하드코딩하지 않는다. 상태는 버전, 원격 URL/브랜치(`origin/main`), 마지막 성공 T SHA, 수집 시각, reportId, 보고서 경로와 IA 갱신 결과를 포함한다. 비밀·토큰은 넣지 않는다.

1. 실행 전 상태와 원격 식별자를 확인한다. 손상/다른 원격의 상태를 첫 실행으로 조용히 취급하지 말고 기준 확인을 요청한다. 동일 저장소의 동시 실행은 전용 잠금 파일을 배타 생성해 방지하고 이미 실행 중이면 알린다. 오래된 잠금을 다른 실행 확인 없이 지우지 않는다.
2. 검증된 보고서와 IA 갱신을 완료한 후 상태를 같은 디렉터리의 임시 파일에 기록하고 교체한다. 커밋/배포 완료 여부를 성공 조건으로 삼지 않는다. 성공은 로컬 결과물 생성·검증 완료를 뜻한다.
3. 중간 실패 시 이전 성공 상태를 유지한다. 부분 결과는 초안으로 알리고 reportId를 보존해 다음 실행에서 같은 항목을 복구한다. 자동으로 반복 재시도하거나 다른 변경을 원복하지 않는다. 결과물 또는 IA 이력이 수동 삭제·미반영된 경우 건너뛰지 말고 이전 보고에서 복구할지 확인한다.
4. 명시한 SHA 재실행은 저장된 시작 기준보다 우선한다. 성공하면 이번 T를 다음 무인자 실행의 기준으로 저장한다. B=T 또는 최종 diff가 없는 경우도 확인 보고서를 만들고 검증 후 T를 저장할 수 있다.
5. 커밋 작성 시각만으로 과거 원격 반영 시각을 확정하지 않는다. 날짜로 시작 범위를 요청받으면 커밋 시각과 실제 main 반영 시각의 차이를 안내하고, 가능하면 확정 SHA를 기준으로 삼는다.

## 검증 기준

- 해시 지정의 포함 규칙과 무인자 실행의 제외 규칙, merge 첫 부모·루트 커밋·다른 브랜치/모호한 해시 처리를 확인한다.
- 전체 원복은 빈 결과, 부분 원복은 남은 hunk만 표시하고, 이전 보고 이후 원복은 유효 변경으로 표시하는지 확인한다.
- 공통 UI, 삭제/이름변경, 동적 참조 한계, 같은 pathname의 query/hash 상태, 공동 담당·미지정, 필터로 숨은 공통 소유자를 확인한다.
- 날짜 Select·보고서 담당자 Select와 네이티브 IA 목록 필터가 독립적인지, 날짜만 있는 URL의 전체208개 등 실제 파일 수·rowspan·Before/After 링크·직접 진입/새로고침/뒤로·앞으로/닫기 URL을 확인한다. 파일 수208은 이번 보고의 사례이며 향후 결과에 하드코딩하지 않는다.
- 재실행 중복, 실패 후 성공 SHA 미전진, 수동 비고·다른 작업 보존, 보고서와 IA의 최종 변경 일치를 확인한다.
- 앱 코드 변경이 있으면 관련 경로 테스트·타입·변경 파일 lint/format, 필요한 Panda 생성·PC/MO 표시를 검증하고 실제 수행 범위만 기록한다. 스킬 문서만 생성·수정한 경우 앱 빌드를 실행할 필요는 없다.
