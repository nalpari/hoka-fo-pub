# 전체 화면 퍼블리싱 인계

사용자 승인 범위는 전체 화면이다. 기존 디자인 반영 결과를 기반으로 서비스·시연 흐름을 제거하며, 새 서비스·업무 규칙을 구현하지 않는다. 기존 디자인 출처는 [UI](../architecture/ui.md)와 [라우팅](../architecture/routing.md)의 화면별 기록을 유지한다. 이 문서는 모든 Figma 픽셀을 새로 대조했다는 뜻이 아니다.

## 표시와 향후 연결 책임

- 인증·API·브라우저 저장·장바구니 변경·주문/견적 계산·삭제·제출 완료 이동을 제거했다. 요청 컨텍스트와 사용되지 않는 서비스 훅도 제거했다.
- 기본 페이지는 준비된 정상 fixture를, 별도 URL은 고정 empty/error/loading/complete/dialog fixture를 표시한다. 입력·체크 후에도 고정 오류는 남는다. 탭·선택·수량·갤러리·첨부 미리보기·모달 열기/닫기는 로컬 UI다.
- ShopShell은 로그인 표시와 cart/wishlist/recent 카운트만 받는다. Profile/Address/Review/Inquiry/Orders/Product/Running의 실제 ID·payload·요청·pending/실패/재시도·성공 갱신은 향후 통합 소유자가 연결해야 한다. 주석은 실제 API 구현을 의미하지 않는다.
- 주문 총액/환불/상품 row 금액과 할인 문구는 명시된 fixture 표시값이다. 수량·쿠폰 선택으로 업무 금액을 재계산하지 않는다.
- 컴포넌트의 한국어/영문 요약, 기존 RoutePreview·Storybook 고정 플랫폼, semantic HTML·접근성과 화면별 스타일 소유권을 유지한다.

## 직접 상태 선정

기존 완료·잠김·오류 URL을 재사용하고 PC/MO는 같은 URL을 사용한다. 이번 채팅에서 추가한 18개 URL은 기존 프로필/주문/상품/리워드/러닝 표현과 stories에 근거한다. 이론상 가능한 상태를 추가하지 않았다. 다른 채팅의 디자인 누락 보완 14개는 같은 작업 트리에 반영되지만 그 소스·커밋 소유권은 별도로 유지한다.

모달/오류/빈 상태는 재현 클릭 순서나 저장값이 없어도 즉시 확인되어야 하므로 분리한다. 사소한 badge·일반 hover/focus·모든 선택 조합은 기본 화면 또는 기존 stories에서 확인하며 URL을 곱하지 않는다. OS 파일 선택창은 제품 화면에서 제외한다.

## 예외와 검증

/screen-index와 /publishing-guide는 내부 도구이며 /support/mileage는 기존 안내 alias다. 고객용 신규 IA를 만들지 않고 별도로 확인한다. 동적 preview의 미등록 slug는 notFound다.

2026-11-02 수행 결과:

- 타입 검사·전체 lint·Panda 생성·Next.js 프로덕션 빌드·Storybook 빌드 통과. Node 테스트 103개 통과. Storybook 빌드의 use client directive 경고는 실행 실패가 아니다.
- IA 고유 URL 222개를 PC 1920px / MO 375px에서 직접 열어 총 444건 확인했다. 컴파일 중 일시 실패한 주소는 안정화 후 재검사했다. 최종 runtime error·예상치 못한 notFound·가로 넘침은 없었다. /preview-not-found의 404 안내는 의도된 표시다.
- 내부 도구 /screen-index·/publishing-guide와 legacy /support/mileage를 별도 확인했다. IA 상태명(저장 확인)·상태 URL 검색과 원본/상태 링크 유지를 확인했다.
- 로그인 오류 URL에서 ID/비밀번호 입력과 submit 후 고정 aria-invalid 2개와 URL 유지를 확인했다. 주문 삭제 모달의 확인/닫기와 새로고침 시 같은 모달 복원을 확인했다. 쿠폰 선택 전후 총액은 350,000원으로 유지하고 결제 버튼은 주문서 URL에 머물렀다.
- 자동 플랫폼 1024=MO, 1025=PC와 1199/1200 경계를 확인했다. 1025~1199px의 1200px PC 캔버스는 의도된 동작이며 1200·2560px에서는 scrollbar로 인한 가로 넘침이 없었다. 열린 프로필 모달을 경계 너비로 resize해 단일 모달과 focus 유지, portal 플랫폼 변경, Escape 닫기를 확인했다.
- 빌드된 Storybook에서 MO fixture를 1920px, PC fixture를 375px에 열어 명시 플랫폼 유지를 확인했다. 주소 고정 오류 및 인증 고정 오류의 play 2건은 입력 완료 후 각각 aria-invalid 6/3 유지와 화면 오류 없음으로 확인했다. 전체 Storybook play suite를 실행한 것은 아니다.
- 브라우저 이미지 캡처는 Page.captureScreenshot timeout이 반복되어 PNG 비교를 완료하지 못했다. DOM·접근성 상태·실제 계산 크기·overflow 기준으로 검증했으며 새 Figma 전수 픽셀 비교 또는 캡처 검증을 주장하지 않는다.

서비스 통합 자체, 실제 서버 요청 성공/실패, 운영 인증·주문·결제는 구현/검증 대상이 아니다. 기존 서비스 시뮬레이션 stories는 고정 표시 확인으로 전환했으며 전체 Storybook play 실행 여부는 위 실제 검사 결과에 별도로 적는다.
